## 智能体设计方案与部署指南

> 参赛赛道：赛道一 · 智能体开发

> 技术底座：智能体平台（腾讯元器 / 扣子 Coze）+ 国产大模型（混元 / 文心 / 通义 / GLM 均可适配）

## 一、作品概述

### 1.1 背景与痛点

C语言「选择结构」单元（if / if-else / 多重 if / 嵌套 if / switch）是程序设计课程的第一个"思维台阶"。教学实践中长期存在三大痛点：

| 痛点 | 具体表现（源自真实作业复盘） |
|------|------|
| **易错点多且反复出现** | `=` 与 `==` 混用、switch 漏 break、`age,14` 逗号代替比较、缩进混乱导致 else 配对看错 |
| **反馈滞后** | 作业一周后才复盘，错误已固化；课堂答疑无法覆盖每个学生 |
| **学情盲区** | 教师难以知道每个学生卡在哪个知识点（是逻辑运算没懂，还是嵌套配对出错） |

### 1.2 作品定位

**小C老师**是一个植入 C语言选择结构单元全流程的教学智能体：课前提供任务式学习路径，课中充当"秒回的助教"，课后完成即时批改、错因诊断与薄弱点预测，将"一周后复盘"压缩为"当秒反馈"。

### 1.3 与赛道要求逐项对应

| 赛道要求 | 本作品实现 |
|---------|-----------|
| 面向教育场景（教、学、管、研、育、评） | 覆盖"教"（知识讲堂、任务讲解）、"学"（闯关路径、AI答疑）、"评"（在线批改、学情分析）、"育"（鼓励式人格、学习习惯提醒） |
| 基于国产大模型 | 系统提示词 + 知识库方案，可直接部署于腾讯元器（混元）或扣子 Coze（可接通义/文心/GLM） |
| 教学功能 | 7大知识点讲解、5大任务引导、20题题库带详细解析 |
| 角色人格 | "小C老师"：亲切耐心的编程教师，启发式提问，善用生活化案例（延续教材中图书馆借书、身高预测、门票打折等实例风格） |
| 交互逻辑 | 对话式意图识别 + 任务闯关状态机 + 分支教学（根据掌握度推进/回退） |
| 数据分析 | 知识点级正确率统计、雷达图、错题记录（原型内置；生产版通过平台变量/数据库持久化） |
| 互动反馈 | 答题即时判分 + 错因讲解 + 连胜激励 |
| 推理预测 | 薄弱点诊断（正确率阈值 + 错误类型规则引擎）+ 单元测验成绩预测（加权模型）+ 个性化练习推荐 |

## 二、智能体人设与系统提示词

> 以下提示词可直接粘贴到元器 / 扣子的「人设与回复逻辑 / System Prompt」输入框。

```text
# 角色
你是「小C老师」，一位年轻亲切、耐心十足的C语言编程教师，专攻《C语言程序设计》第四单元「选择结构程序设计」。你的教学对象是刚接触程序设计的职校/本科学生。

# 知识范围（严格限定）
你只回答以下内容相关的问题，超出范围时友好引导回来：
1. 单分支 if 语句（任务1：身高预测）
2. 双分支 if-else 语句（任务2：闰年判断）
3. 多重 if 语句（任务3：划分考试成绩等级）
4. 嵌套 if 语句（任务4：旅游景点门票打折）
5. switch 语句（任务5：设计小型计算器）
6. 关系运算符、逻辑运算符（&&、||、!）与真值表
7. 条件运算符 ?: 与短路运算
8. 本单元常见编程错误（=与==、漏break、漏大括号、逗号表达式、缩进与else配对）

# 教学风格
- 启发式：先反问引导思路，再给答案。学生问"闰年怎么判断"时，先问"你觉得'被4整除'用C语言怎么写？"，学生尝试后再讲解。
- 生活化：尽量用教材同款案例讲解（图书馆借书→单/双分支；身高预测→独立条件；门票→嵌套；计算器菜单→switch）。
- 鼓励式：学生答错时先肯定思路中正确的部分，再指出问题；连续答对3题要主动表扬。
- 代码规范：给出的代码必须缩进整齐、if/else体一律加大括号、判断用==不用=。

# 回答格式要求
- 讲语法时：先给【语法格式】代码块，再给【执行过程】一句话，再给【生活实例】，最后给【易错提醒】。
- 讲错题时：先指出错误类型，再给修改后的代码，最后总结一条避坑口诀。
- 代码使用 ```c 代码块，关键行用注释标注。
- 单次回复控制在300字以内，宁可分两次问，不要一次灌太多。

# 特殊能力（由平台工作流触发，对话中也可以口头引导）
- 学生说"我哪里薄弱/怎么复习"时：引导其查看学情分析面板，或根据其答题记录给出针对性建议。
- 学生要求出题时：从题库中按知识点抽题，一次一题，等学生作答后再公布解析并追问是否继续。

# 边界
- 不代写整份作业，可以讲解思路、批改代码、逐步引导。
- 涉及作业抄袭、考试作弊的请求，温和拒绝并转化为学习建议。
```

## 三、知识库设计

### 3.1 知识库文件结构（上传到平台知识库）

```
xiaoc-kb/
├── 01-知识点/
│   ├── 单分支if语句.md        （语法、流程、图书馆借书实例、3条易错点）
│   ├── 双分支if-else语句.md
│   ├── 多重if语句.md          （含"半幅条件顺序不能颠倒"专题）
│   ├── 嵌套if语句.md          （含"else与最近未配对if配对"专题）
│   ├── switch语句.md          （含"break贯穿执行"专题、判断天数案例）
│   ├── 关系与逻辑运算.md       （真值表、优先级、"非0即真"）
│   └── 条件运算符与短路.md     （右结合、短路跟踪表法）
├── 02-任务案例/
│   ├── 任务1-身高预测.md      （题目、思路指导、完整代码、运行结果）
│   ├── 任务2-闰年判断.md
│   ├── 任务3-成绩等级.md
│   ├── 任务4-门票打折.md
│   └── 任务5-小型计算器.md    （含优化版对比）
├── 03-题库/
│   ├── 选择题库-20题.md       （每题标注知识点、答案、解析、错因类型）
│   └── 编程题库-4题.md        （字符分类、个税计算、三数排序、产品分级）
└── 04-易错档案/
    └── 高频错误TOP5.md        （=与==、漏大括号、漏break、逗号比较、缩进混乱）
```

> 知识库内容全部提炼自《C语言》第四单元教材课件（国家精品资源共享课程配套教材），确保教学准确性。原型网页中已内置全部内容可供核对。

### 3.2 知识库调优建议

- 检索配置选择**语义匹配**，Top-K = 3；
- 每个文档开头写一行"本页讲解：XX，适用于XX问题"，提高召回精度；
- 题库文档按"一题一段"切分，保证检索命中后上下文完整。

## 四、工作流设计

### 4.1 主对话流（平台内置 LLM 节点即可）

```
用户输入 → 意图识别（LLM）
 ├─ 知识提问 → 检索知识库(01/02) → 按"语法/过程/实例/易错"四段式回答
 ├─ 请求出题 → 检索题库(03) → 单题输出 → 等待作答 → 判分+解析
 ├─ 提交代码/报错 → LLM 代码审查 → 指出错误类型+修正+口诀
 ├─ 学情咨询 → 读取用户答题数据 → 生成建议+推荐练习
 └─ 超纲闲聊 → 人格化引导回学习
```

### 4.2 批改工作流（扣子示例，节点编排）

```
[开始] → [意图分类] →(出题/答题模式)
 → [知识库检索:题库] → [LLM: 抽题]
 → [等待用户输入答案]
 → [代码节点: 判分]
      ├─ 正确 → [LLM: 表扬+追问"再来一题?"] → [数据库: 记录 qid, kp, ✓]
      └─ 错误 → [知识库检索: 该题解析+对应知识点易错档案]
              → [LLM: 错因讲解] → [数据库: 记录 qid, kp, ✗]
```

### 4.3 学情分析与预测工作流（定时/触发式）

```
[触发: 累计答题≥5 或 用户请求]
 → [数据库查询: 按知识点聚合正确率]
 → [代码节点: 计算掌握度]（正确率≥80% 掌握 / 60~79% 一般 / <60% 薄弱）
 → [代码节点: 测验预测]（已测按正确率、未测按50%基线，加权平均→预测分）
 → [LLM: 生成个性化诊断报告与复习建议]
 → [输出] + [可选: 推送提醒]
```

**预测模型说明**（原型已实现）：`预测分 = Σ(知识点正确率或基线50) / 7`，置信度随答题数增长（`min(95%, 40% + 4%×答题数)`）。生产版可升级为逻辑回归/知识追踪（BKT/DKT）模型。

## 五、平台部署指南

### 5.1 腾讯元器（推荐，可分享到微信）

1. 访问 yuanqi.tencent.com → 创建智能体 → 选择"从头创建"。
2. **基本信息**：名称「小C老师」，头像用"C"字蓝色圆形徽标，简介"C语言选择结构智能助教"。
3. **人设与回复逻辑**：粘贴本文档第二节的系统提示词。
4. **知识库**：新建知识库，上传 `xiaoc-kb/` 全部文档，检索模式选语义匹配。
5. **扩展能力**（可选）：添加"数学/代码"插件辅助计算；发布到微信小程序/公众号，学生扫码即用。
6. 测试问题清单：`if和else怎么配对`、`switch漏break`、`闰年条件`、`=和==的区别`、`出题考考我`。

### 5.2 扣子 Coze（推荐，工作流能力强）

1. 访问 coze.cn → 创建智能体（Bot）。
2. **人设与提示词**：粘贴第二节的系统提示词；模型选通义千问/文心/GLM 任一国产模型。
3. **知识库**：上传 `xiaoc-kb/` 文档；命中策略"按需匹配"，最大召回 3。
4. **创建工作流**：
   - `quiz_flow`：按 4.2 节节点编排（开始→检索→抽题→判分→解析→记录）；
   - `analysis_flow`：按 4.3 节编排（查询→统计→预测→生成报告）；
   - 在 Bot 中添加这两个工作流，并在提示词中说明触发词（"出题"/"我的学情"）。
5. **数据库**：新建表 `answer_record(user_id, qid, kp, is_correct, created_at)`。
6. **发布**：一键发布到微信公众号、豆包或网页 SDK，获取分享链接给学生。

### 5.3 演示原型与生产版的关系

| 能力 | 演示原型（HTML，随附文件） | 生产版（平台部署） |

### 5.4 API 直连模式（演示原型的"真AI"形态）

演示原型内置**大模型 API 引擎**，无需部署后端，配置 API Key 后即可从"本地规则匹配"升级为"真AI"：

**能力升级对照**

| 功能 | 本地演示模式（默认） | API 直连模式（配置后） |
|------|--------------------|-----------------------|
| AI 答疑 | 关键词匹配，只能答知识库内 20 类问题 | 真·多轮对话，任何 C 语言问题、贴代码找错，流式输出 |
| 错题讲解 | 固定解析文案 | 解析下方出现"追问小C老师"按钮，AI 结合错题逐题深讲 |
| 学情诊断 | 规则阈值诊断 | 新增"AI 深度诊断报告"：大模型逐题分析错因、生成三步提升计划与测验预测 |

**配置步骤（3 分钟）**

1. 打开原型，点击右上角 `⚙️` 或顶部"本地演示模式"徽章，唤出「大模型 API 设置」面板；

**技术实现要点**（答辩可讲）

- 采用 **OpenAI Chat Completions 兼容协议** + **SSE 流式传输**（`fetch` + `ReadableStream` 逐 token 渲染），天然适配全部主流国产大模型；
- 每次请求动态构建**系统提示词**：小C老师人设 + 第四单元知识图谱 + **学生实时学情**（各知识点正确率、薄弱点、错题清单）自动注入，实现个性化回答；
- 对话历史保留最近 13 条消息控制上下文长度；API 失败（断网/Key 失效/限流）时**自动回退本地知识库**，保证演示永不冷场——这本身就是一个很好的容错设计案例。

**答辩演示建议**：先在断网/未配置状态展示本地模式（说明离线兜底能力），再现场配置 Key 展示真AI对话与"AI 深度诊断报告"，形成"规则引擎 → 大模型"的能力对比叙事，直观呼应赛道"基于国产大模型开发信息系统"的要求。

## 六、答辩演示脚本（5分钟）

1. **开场痛点**（30s）：展示作业复盘中的真实错误截图——`if(age=65)`、`age,14`、缩进错乱——"这些错误要等一周后才被老师发现"。
2. **角色人格**（30s）：打开AI答疑，问"你是谁"，展示小C老师人设与知识边界。
3. **教学功能**（60s）：问"闰年怎么判断"→ 展示启发式反问；再问"帮我讲讲"→ 展示"语法/过程/实例/易错"四段式讲解。
4. **互动反馈**（60s）：进入在线练习，故意答错一道 switch 题 → 展示即时错因讲解与避坑口诀；点击"追问小C老师"展示 AI 逐题深讲（需已配置 API）。
5. **数据分析+推理预测**（90s）：进入学情分析 → 雷达图、薄弱点诊断（准确指出薄弱知识点与推断原因）、测验成绩预测与置信度 → 点击"针对薄弱点练习"展示个性化推荐闭环。
6. **落地说明**（30s）：展示部署指南——元器/扣子 1~2小时上线，学生微信扫码即用。
